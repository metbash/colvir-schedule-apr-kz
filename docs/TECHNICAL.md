## Архитектура проекта

Проект реализован как **SPA (Single Page Application)** на чистом JavaScript (ES2020+) без фреймворков.  
Вся бизнес-логика вынесена в модули папки `src/`, UI — в `index.html`.

```
colvir-schedule-apr-kz/
├── index.html              # Главная страница: UI + точка входа
├── src/
│   ├── models/             # Модели данных (Loan, GracePeriod, Schedule)
│   ├── services/           # Высокоуровневый сервис расчёта
│   ├── engine/             # Движки расчёта (Annuity, EqualPrincipal)
│   ├── builders/           # CashFlowBuilder — построение потоков платежей
│   ├── processors/         # Постпроцессоры (льготы, округление и др.)
│   ├── math/               # APRCalculator — численный расчёт ГЭСВ
│   ├── calendar/           # KazakhstanBusinessCalendar
│   ├── core/               # Константы (APR.BASIS_DAYS и др.)
│   └── tools/              # Вспомогательные утилиты
├── docs/                   # Документация
├── test-data/              # Тестовые данные
└── README.md
```

## Структура файлов

### `src/models/Loan.js`
Модель займа. Хранит все входные параметры:
- `principal` — сумма займа
- `annualRate` — годовая ставка (%)
- `term` — срок (месяцев)
- `issueDate` — дата выдачи
- `firstPaymentDate` — дата первого платежа
- `lastPaymentDate` — дата последнего платежа
- `paymentMethod` — метод погашения (`ANNUITY` | `EQUAL_PRINCIPAL`)
- `distributionMode` — режим распределения льготы
- `gracePeriods[]` — массив льготных периодов

### `src/models/GracePeriod.js`
Модель льготного периода:
- `startPeriod`, `endPeriod` — диапазон периодов
- `odGrace` — отсрочка ОД
- `percentGrace` — отсрочка процентов

### `src/services/LoanCalculator.js`
Оркестратор расчёта. Принимает `Loan`, выбирает нужный движок, применяет постпроцессоры, возвращает `{ schedule, apr }`.

### `src/engine/`
Движки расчёта под каждый метод погашения.

### `src/builders/CashFlowBuilder.js`
Строит итоговый список денежных потоков для расчёта ГЭСВ.

### `src/math/APRCalculator.js`
Численный расчёт ГЭСВ методом итераций (Newton-Raphson или бисекция).

### `src/calendar/KazakhstanBusinessCalendar.js`
Производственный календарь Казахстана. Сдвигает даты платежей с выходных и праздников на ближайший рабочий день.

### `src/core/Constants.js`
Глобальные константы:
```js
export const APR = {
    BASIS_DAYS: 365   // база для расчёта ГЭСВ по законодательству РК
};
```

## Производственный календарь КЗ

Календарь содержит список **праздничных дней** Республики Казахстан и реализует метод:

```js
calendar.adjustPaymentDate(date) → Date
```

Логика:
1. Если дата попадает на субботу — сдвиг на понедельник
2. Если дата попадает на воскресенье — сдвиг на понедельник
3. Если дата попадает на официальный праздник — сдвиг на следующий рабочий день
4. Повторять до первого рабочего дня

**Праздничные дни РК (жёстко зашиты):**
- 1-2 января — Новый год
- 7 января — Православное Рождество
- 8 марта — МЖД
- 21-23 марта — Наурыз
- 1 мая — День единства народа
- 7 мая — День защитника Отечества
- 9 мая — День Победы
- 15 ноября — День Республики
- 16-17 декабря — День Независимости

## Расчёт процентов

### Формула начисления вознаграждения за период

Вознаграждение рассчитывается по **фактическому числу дней** (ACT/365):

$$I_n = B_{n-1} \times r \times \frac{d_n}{365}$$

Где:
- \( I_n \) — проценты за период \( n \)
- \( B_{n-1} \) — остаток ОД на начало периода
- \( r \) — годовая ставка в долях (например, 0.20 для 20%)
- \( d_n \) — количество дней между датой предыдущего и текущего платежа
- \( 365 \) — база дней по законодательству РК (`APR.BASIS_DAYS`)

### Количество дней в периоде

$$d_n = \text{paymentDate}_n - \text{paymentDate}_{n-1}$$

Для первого периода:
$$d_1 = \text{firstPaymentDate} - \text{issueDate}$$

---

## Метод аннуитета

Аннуитет — метод, при котором **каждый платёж одинаков** в течение всего срока.

### Формула аннуитетного платежа

Поскольку периоды неравномерные (разное количество дней в месяцах, праздники), применяется **обобщённая аннуитетная формула** с дисконтированием реальных дат:

$$A = \frac{P}{\sum_{n=1}^{N} \prod_{k=1}^{n} \frac{1}{1 + r \cdot \frac{d_k}{365}}}$$

Где:
- \( A \) — аннуитетный платёж
- \( P \) — сумма займа
- \( N \) — количество периодов
- \( d_k \) — дней в периоде \( k \)
- \( r \) — годовая ставка в долях

### Итерационное построение графика (аннуитет)

Для каждого периода \( n \):

1. Начисляем проценты:
$$I_n = B_{n-1} \times r \times \frac{d_n}{365}$$

2. ОД за период:
$$OD_n = A - I_n$$

3. Остаток ОД:
$$B_n = B_{n-1} - OD_n$$

4. В последнем периоде ОД = оставшемуся остатку (закрытие копеечных расхождений).

---

## Метод равных частей ОД

Каждый месяц погашается **одинаковая часть** основного долга.

### Формула ОД за период

$$OD_n = \frac{P}{N}$$

Проценты при этом каждый месяц уменьшаются, так как уменьшается база:

$$I_n = B_{n-1} \times r \times \frac{d_n}{365}$$

Полный платёж каждый месяц разный:
$$A_n = OD_n + I_n$$

Максимальный платёж — в первом периоде, минимальный — в последнем.

## Льготные периоды

### Льгота по ОД (`odGrace: true`)

В льготном периоде ОД не погашается (`OD_n = 0`). Платёж = только проценты.

Отложенная сумма ОД распределяется на оставшиеся периоды:

**Режим «На все предстоящие»:**
$$OD^*_k = OD_k + \frac{\sum_{grace} OD_{grace}}{N_{remaining}}$$

Где \( N_{remaining} \) — количество незальготных периодов после льготных.

**Режим «На первый предстоящий»:**
Вся сумма добавляется к первому незальготному платежу:
$$OD^*_{first} = OD_{first} + \sum_{grace} OD_{grace}$$

### Льгота по процентам (`percentGrace: true`)

Аналогично, проценты в льготном периоде = 0. Отложенные проценты перераспределяются на оставшиеся периоды по тому же принципу.

## Расчёт ГЭСВ (APR)

**ГЭСВ** — Годовая Эффективная Ставка Вознаграждения. Рассчитывается по методологии **НБРК (Национального Банка РК)** и отражает реальную стоимость займа с учётом всех комиссий и фактических дат платежей.

### Уравнение для ГЭСВ

ГЭСВ — это ставка \( r^* \), при которой NPV (чистая приведённая стоимость) всех денежных потоков равна нулю:

$$0 = -P_{net} + \sum_{n=1}^{N} \frac{CF_n}{\left(1 + r^*\right)^{t_n}}$$

Где:
- \( P_{net} = P - fee \) — сумма займа за вычетом единоразовой комиссии
- \( CF_n \) — платёж в период \( n \)
- \( t_n = \frac{D_n}{365} \) — время в годах от даты выдачи до даты платежа \( n \)
- \( r^* \) — искомый ГЭСВ (в долях)

### Метод решения

Уравнение решается численно итерационным методом **Newton-Raphson**:

$$r^*_{i+1} = r^*_i - \frac{f(r^*_i)}{f'(r^*_i)}$$

Где:
$$f(r) = -P_{net} + \sum_{n=1}^{N} CF_n \cdot (1+r)^{-t_n}$$

$$f'(r) = -\sum_{n=1}^{N} t_n \cdot CF_n \cdot (1+r)^{-t_n - 1}$$

Начальное приближение: \( r^*_0 = \) годовая номинальная ставка займа.

### Учёт единоразовой комиссии

Если задана единоразовая комиссия `fee`, она добавляется как **отдельный денежный поток** на дату выдачи:

```
cashFlows = [
  { date: issueDate, amount: -(principal - fee) },  // выдача
  ...платежи...,
  { date: issueDate, amount: fee }                  // комиссия
]
```

Это увеличивает ГЭСВ по сравнению с номинальной ставкой.

## Excel-экспорт

Экспорт реализован **без внешних библиотек** — генерируется чистый OOXML (Office Open XML), который упаковывается в ZIP-архив с CRC32 и Local File Headers вручную (реализация на чистом JS).

### Структура XLSX-файла

```
[Content_Types].xml
_rels/.rels
xl/workbook.xml
xl/_rels/workbook.xml.rels
xl/worksheets/sheet1.xml
xl/sharedStrings.xml
xl/styles.xml
```

### Форматы чисел

| numFmtId | Код | Описание |
|----------|-----|----------|
| 164 | `#,##0.00` | Денежные суммы |
| 165 | `DD.MM.YYYY` | Даты |
| 166 | `#,##0.00;[RED]-#,##0.00` | (резерв) |

### Конвертация дат в Excel

Excel хранит даты как число дней с **30.12.1899** (баг Lotus 1-2-3, унаследованный Excel):

$$excelDate = \frac{jsTimestamp - UTC(1899, 11, 30)}{86400000}$$

## Слабые места и рекомендации

### 🔴 Критические

| Проблема | Описание | Рекомендация |
|----------|----------|--------------|
| **Нет автотестов** | Расчёты не покрыты unit-тестами | Добавить Jest/Vitest тесты для `APRCalculator`, движков аннуитета и равных частей ОД |
| **Праздники захардкожены** | Список праздников РК зашит в код, нет логики переносов | Перенести в JSON-файл, добавить механизм переносов (постановления Правительства РК) |
| **Нет валидации дат** | Если `lastPaymentDate` < `firstPaymentDate` — ошибка без описания | Добавить явную валидацию входных данных с понятными сообщениями |

### 🟡 Важные

| Проблема | Описание | Рекомендация |
|----------|----------|--------------|
| **Нет bundler/build** | Модули грузятся по одному через браузерные `import` | Добавить Vite или esbuild — ускорит загрузку и снимет CORS-ограничение |
| **Всё в одном HTML** | `index.html` содержит ~800 строк JS и CSS | Разделить на отдельные файлы: `app.js`, `styles.css` |
| **Нет сохранения состояния** | При перезагрузке все данные теряются | Добавить `localStorage` для автосохранения последних параметров |
| **ГЭСВ не пересчитывается автоматически** | После ручного редактирования нужно жать кнопку | Добавить автопересчёт при изменении |
